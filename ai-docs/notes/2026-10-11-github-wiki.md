# GitHub wiki for 0.1.2

## Summary

The owner asked for the wiki after the 0.1.1 release and saved the first page. Eleven pages were written with the wikiwright skill from the repository, the research notes, the eval runs and a verification program that downloads the published release zip and runs every page example from it. The first program run, against 0.1.1, found two bugs (below); they were fixed and released as 0.1.2, and the pages describe 0.1.2. Wiki commit bccdc61; `live`: 11 pages, 0 failures, anchors 12 links, 0 broken. Prose checker: 0 strong, 13 weak (long sentences, one hedge).

Pages: Home, Getting-Started, The-Skills, Commands, How-Checks-Decide, The-Asset-Contract, Errors-and-Edge-Cases, Recipes, Versions-and-Upgrading, FAQ, Development, plus _Sidebar and _Footer.

polywright is neither an npm nor a NuGet package: it is a plugin of agent skills plus a Python command-line tool, released only as GitHub release zips. The page set was the command-line-tool set with The-Skills, How-Checks-Decide and The-Asset-Contract in place of an API reference; no registry, no golden captures.

## Where the pages are

The wiki's working copy is the sibling folder `polywright.wiki` next to this clone (outside this repository), branch `master`, remote `origin` = `https://github.com/m4bwav/polywright.wiki.git`. The pages were generated by a builder script that copies each output block from the saved verification output; the builder lived in the session scratchpad and is not kept, so later edits are made to the pages directly. Plain markdown links, no wikilinks, LF line endings.

## How it was published

Preflight state: placeholder (the owner's first page). The pages were committed on top of it and pushed with a plain `git push` (fast-forward). `wikiwright.py live m4bwav/polywright <wiki dir>`: 11 pages, 0 failures, sidebar and footer render, anchors 0 broken.

## Updating the wiki later

1. `git -C <wiki dir> pull --ff-only`, then edit the pages.
2. Re-verify: `python ai-docs/notes/2026-10-11-wiki-verify.py <new version> > new.out.txt` from the repository root (it downloads that release's zip into a temp folder and runs there; it needs Blender, numpy, Pillow and trimesh), then `python <wikiwright>/scripts/wikiwright.py diffout ai-docs/notes/2026-10-11-wiki-verify.out.txt new.out.txt`. Every changed section is a page to fix. Save the new output over the old one.
3. `wikiwright.py outputs <wiki dir> <new output> --address ''`, `wikiwright.py snippets <wiki dir> ai-docs/notes/2026-10-11-wiki-verify.py`, `wikiwright.py check <wiki dir> --version <new>`, and the everwrite checker.
4. Commit, push, `wikiwright.py live m4bwav/polywright <wiki dir>`. Pages that name the version: _Footer, Home (current release line), Commands and Errors-and-Edge-Cases (first sentence), Getting-Started (zip name and `--version` output), Versions-and-Upgrading (table).

## Facts verified while writing (not in the README)

- Output paths are relative to the working folder and use the OS separator (`park\\solid.stl` on Windows).
- A manifest source without a licence is kept and reported as a problem on every later `manifest` call (exit 1) until it has one.
- `check` exits 1 only on `fail`; `warn` exits 0.
- `bpy` reports Blender's exit code 3 for a Python error (pw.py passes `--python-exit-code 3`).
- `place` reads `<out>/data/osm.json` when it exists ("OSM from cache"), so a second run asks no server.
- The ComfyUI TRELLIS.2 and Pixal3D template defaults to Pixal3D; node 316 switches to TRELLIS.2.

## Inaccuracies found in the shipped docs

1. Release 0.1.1: `pw.py --version` printed `0.1.0` while `plugin.json` said 0.1.1. Fixed in 0.1.2; `check_skills.py` now fails when they differ.
2. Release 0.1.1: `printable` on an open flat surface lying on the ground returned `watertight: false` with 59,198 non-manifold edges; the README's claim "any mesh to one watertight solid" was false for that case. Fixed in 0.1.2 (re-ground before the base clamp), with a regression test.
3. Release 0.1.1: the planar dissolve in `printable` could run for more than ten minutes on a few hundred thousand faces. Fixed in 0.1.2.
4. README (0.1.0 to 0.1.2) says the TRELLIS.2 workflow is "not verified yet"; it ran on 2026-10-11 after 0.1.2 was tagged (the skills' docs on main now say so; the README changes with the next release).

## Gotchas

- `outputs` and `snippets` markers go on the line before a block; a `text` fence is read as output, so plugin slash commands need `<!-- outputs: skip -->`, not a snippets marker.
- A file's first line must sit on its own line in the program for `snippets` to find it (`HELLO = """` then the file's lines).
