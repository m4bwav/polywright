# Plan: `pw.py duel`, a two-fighter previs for AI video controls

Date: 2026-10-17. Status: approved by the owner ("plan then PR"), built on branch `duel` (see "Result" at the end).

## Why

A film's AI video takes (MiniMax H3 with Fun ControlNet Union 2.0: Canny, depth, pose) used Canny renders of
the empty set as the control. They hold the room and the camera, never the people, and two-shots drift to both
fighters facing the lens (field lesson 128). A Blender previs with two posed mannequins in the room fixed a
duplicated fighter and the start and end states of a floor shot (Canny of the clay with figures), and depth with
thick blades held the near fighter's back to the camera through the action (field H3 test, 2026-10-17). The
prototype lives in the film's own folder; this moves its generic parts into polywright so any two-fighter shot
gets the same controls from one JSON file. Background: [crowd-blockouts.md](../../skills/polywright/references/crowd-blockouts.md)
"Two fighters".

## Interface

```
python pw.py duel DUEL.json [--out DIR] [--preview] [--check] [--gpu] [--samples 4] [--any-size] [--save-blend] [--timeout 3600]
```

- `--check`: validate the file and print the frame schedule, no Blender.
- `--preview`: render only frame 1, the `check_s` frames and the last frame (seconds, for the sheet).
- `--out`: default `<folder of DUEL.json>/<name>/`.

The duel file (paths relative to it; coordinates in Blender metres, +Z up):

| Key | Meaning |
|---|---|
| `name` | output prefix: `<name>_<pass>.mp4`; default the file's stem |
| `size`, `frames`, `fps` | default 864x480, 73, 24; checked like `crowd` (sides /16; Wan 4n+1 or H3 17k+5) unless `--any-size` |
| `room` | `{"blend": "set.blend"}` (opened), `{"script": "room.py", "call": "build"}` (run in Blender, then `build()` called; the script sees the duel file as `DUEL`), or absent (a 30 m floor) |
| `camera` | `{"pos": [x,y,z], "aim": [x,y,z], "lens": 50}` or `{"object": "CameraName"}` from the room (with an optional `lens`) |
| `origin` | `[x, y]` added to every mark and landing point, so a set plan's coordinates paste in unchanged |
| `fighters` | name -> `mark` [x,y], `facing` (compass bearing in degrees, 0 faces +Y, 90 faces +X, or another fighter's name), `scale`, `tint`, `weapons` {"right": length_m, "left": length_m}, `cloak` (hood and cloak parts), `keys` [[seconds, pose name], ...] |
| `poses` | named poses: a `base` pose plus overrides of `root` [x,y], `yaw`, `pelvis_z`, `spine`, `chest`, `rhand`/`lhand` (from the shoulder), `rblade`/`lblade` (direction or null), `rfoot`/`lfoot`, in the fighter's frame (faces +X, left +Y). Built in: stand, guard, guard_low, kneel |
| `fly` | props leaving a hand or a back: `fighter`, `parts` (rblade, rguard, lblade, lguard, hood, cloak), `t0`, `t1`, `to` [x,y], `arc`, `spin` (turns), `rest_z`, `land_yaw` |
| `near`, `far` | inverse-depth range in metres (one per shot), default 1 and 30 |
| `thick_blade_m` | blade cross-section in the thick-depth pass, default 0.045 (the real blade is 1.6 x 0.6 cm) |
| `canny` | low and high thresholds, default [12, 40] |
| `check_s` | seconds shown on the sheet and rendered by `--preview` |

Output in `--out`: `clay/` (Workbench, fighters tinted, twice the size, for repainting a start frame),
`canny/` (Canny of the clay at the video size), `depth/` (inverse depth, real blades), `depth_thick/` (blades
`thick_blade_m` square), `pose/` (COCO-18 skeletons, nose, eyes and ears left out when turned from the lens),
one `<name>_<pass>.mp4` per pass (ffmpeg), `joints.json`, `camera.json`, `sheet.png` (rows canny, depth,
depth_thick, pose, clay; columns frame 1, `check_s`, last frame). The JSON result reports each fighter's share of
joints inside the frame at the first and last frame and warns under one half (an end state the camera cannot see,
as on the field test's floor shot).

## What it reuses (no copies)

- pw.py: `draw_pose_frames` (gains a width cap and skips hidden ankles), `encode_passes` (gains a prefix),
  `crowd_sheet` (gains chosen frames and labels), the size and frame-count check (split out of `cmd_crowd`),
  `hidden_face_points` (moved from pw_bpy.py to pw.py as plain tuple maths so it is tested without Blender; pw_bpy
  imports it for crowd and duel alike).
- pw_bpy.py: the crowd mannequin's mesh helpers (lifted out of `crowd_meshes`), `seg`, the inverse-depth material
  and depth render (split out of `act_crowd` into helpers both use), the COCO-18 order, `bpy_action`.
- New: the pose library, base-pose resolution, smoothstep keys, two-bone IK, blades and thrown props from the
  prototype, a Canny in numpy (Blender ships numpy; pw.py stays stdlib), the room and camera hooks.
- Pose resolution runs in pw.py: Blender gets one resolved pose per fighter per frame, so the interpolation is
  tested on the standard library alone.

## Tests (tests/test_pw.py)

Without Blender: file validation (missing fighter fields, unknown pose, a base cycle, keys out of order, a fly
part the fighter lacks, size and frame count), pose resolution and smoothstep interpolation (midpoint, null blade
switches at half), frame timing (`check_s` to frames, preview set), facing toward another fighter, face-point hiding
(front, back, profile), `--check` output. With Blender: the example in `--preview` writes every pass and the
sheet, and a back to the camera loses its face points.

## Effort

About 2 to 3 agent hours: one for the code moved from the prototype, one for tests and docs, the rest for the
headless run and the sheet check.

## Not in this step

Fighter and weapon masks, layout boxes, a contact-gap report, rigged bodies for falls (Mixamo or Kimodo), a
depth-plus-Canny composite pass (the field note's open question). Each is a later, separate change.

## Result (2026-10-17)

- Built as planned. pw.py +13.5 KB, pw_bpy.py +14.2 KB (about 590 lines added across both, part of it the helpers
  split out of crowd), examples 2.6 KB. Installed skills folder 567 to 600 KB: still YELLOW, 200 KB under red. The
  hub SKILL.md stays green at 2,499 tokens after tightening the crowd steps.
- Tests: 7 without Blender, 2 with it; the whole suite (49) passes on Windows 11 with Blender 5.2.1, recipes 11/11.
- The example ran end to end: preview (6 frames) in 8 s, the full 73 frames with five mp4s in 35 s. The sheet shows
  A's back to the camera (no nose or eyes in pose), B facing the lens, the blade a solid bar in depth_thick, and
  B's blade landing on the floor.
- The numpy Canny against OpenCV's (`cv2.Canny` after a 3x3 blur, 12/40) on three frames: 97 to 100 percent of
  edge pixels within one pixel of each other.
